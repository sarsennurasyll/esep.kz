# Esep.kz — инструкции для Claude Code

Общие архитектурные правила и Git-правила проекта — в [AGENTS.md](AGENTS.md). Этот файл добавляет текущий продуктовый контекст и правила работы с банковскими данными.

## Цель продукта

Помогать правильно понимать движение денег по банковским выпискам: отличать реальные доходы и расходы от собственных переводов, наличных, долгов и возвратов, распознавать продавцов и честно показывать операции с неизвестным назначением.

## Рабочая стратегия

**Conditional Go — Hybrid** (рабочая гипотеза, не окончательное решение):

- ядро — модель движения денег: направление, банковский тип, тип движения, контрагент и назначение хранятся раздельно, «назначение неизвестно» — допустимое состояние;
- Merchant Knowledge Base сохраняется, но содержит только юрлица и сети; данные о физлицах и ИП в общую базу не попадают;
- целевую аудиторию выбирают эксперименты E1–E3. До их результатов новые продуктовые функции не начинать.

## Банковские данные

- Реальные выписки хранятся только вне репозитория. Не копировать их в проект, `target/`, логи, тесты и документы.
- Анализ реальной выписки — только локально, в памяти или во временном каталоге вне Git; в документы попадают только агрегаты с указанным знаменателем.
- Не публиковать ФИО, номера карт и счетов, IBAN, телефоны, ИИН/БИН частных лиц, остатки и тексты отдельных операций.
- Тестовые данные — только синтетические. Имена в тестах — явно вымышленные шаблоны.
- Сообщения об ошибках, логи и HTTP-ответы не должны содержать описание, сумму или контрагента операции.
- Не передавать данные выписок внешним AI API и сторонним сервисам.
- Репозиторий публичный: перед каждым push проверять diff на персональные данные.

## Проверка кода

```bash
JAVA_HOME=$(/usr/libexec/java_home -v 21) mvn -q -B test
```

Системная `java` может быть 17 — проект требует JDK 21. Тесты используют H2 и не должны подключаться к рабочей PostgreSQL. В отчёте указывать число тестов, failures, errors, skipped.

## Локальный режим (ADR-0002)

- Сервис слушает `127.0.0.1` и принимает только `Host` из `ESEP_ALLOWED_HOSTS` (по умолчанию `localhost,127.0.0.1`). Чтобы открыть сервис с другого устройства, нужно изменить `SERVER_ADDRESS` и `ESEP_ALLOWED_HOSTS` — это осознанное решение владельца.
- Формы защищены CSRF-токеном; `/api/**` принимает изменяющие запросы без `Origin` или с собственным `Origin`.
- В `@WebMvcTest` подключать `@Import(LocalSecurityConfiguration.class)`, POST-формам — `.with(csrf())`.
- Аутентификации нет: внешних пользователей пускать нельзя до реализации варианта C из ADR-0002.

## GitHub workflow

- Репозиторий: `https://github.com/sarsennurasyll/esep.kz`, аккаунт владельца `sarsennurasyll`.
- Автор коммитов задан локально в `.git/config` (официальный noreply-адрес аккаунта). Глобальные настройки не менять.
- Работа идёт в рабочей ветке (сейчас `hybrid/foundation`). Разрешено: commit проверенных изменений и push в рабочую ветку.
- Без отдельного согласования запрещено: push и merge в `main`, force push, удаление веток, переписывание истории, удаление функциональности без обоснования, изменение production-данных.
- Conventional Commits: тип на английском, описание на русском. Файлы добавлять по одному пути после просмотра.
- Перед commit: `mvn test` зелёный, `git status` и `git diff` просмотрены, секретов и персональных данных нет.
