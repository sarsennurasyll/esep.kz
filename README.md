# Esep

Esep — веб-приложение для анализа банковских выписок. Оно импортирует PDF-выписку Kaspi Gold, разделяет движение денег на покупки, переводы людям, наличные и собственные перемещения и честно показывает, какая часть сумм имеет неизвестное назначение.

Главная идея: банковская выписка не говорит, *зачем* был сделан перевод. Поэтому Esep не угадывает назначение, а определяет только то, что следует из данных, и даёт пользователю один раз разметить контрагентов, назначение операций с которыми знает только он.

**Статус.** Проект в активной разработке и работает в локальном режиме на `127.0.0.1`. Аутентификации и разделения пользователей пока нет, поэтому публиковать приложение в интернете нельзя. Путь к публичному сервису описан в [ADR-0005](docs/adr/0005-path-to-production.md).

## Возможности

- **Импорт Kaspi Gold PDF.** Все типы операций (покупка, перевод, пополнение, снятие, «разное»), период из шапки, сверка сумм с итогами шапки по каждому типу. Неизвестный новый тип операции помечается, а не ломает импорт.
- **Модель движения денег.** У каждой операции отдельно хранятся банковский тип, тип движения (покупка, возврат, перевод человеку, внесение или снятие наличных, комиссия), источник и уверенность решения, назначение.
- **Помесячный отчёт** с теми же правилами: доход, расходы, наличные, свои деньги и доля неизвестного по каждому месяцу. Месяцы, которые загруженные выписки покрывают не целиком, отмечены как неполные.
- **Честный отчёт.** Доход — только поступления, отмеченные пользователем как доход. Внесение собственных наличных и переводы между своими счетами не считаются ни доходом, ни расходом. Суммы с неизвестным назначением показаны отдельно, вместе с их долей.
- **Разметка назначения по контрагенту.** Правило «контрагент + направление → назначение» применяется ко всем прошлым и будущим операциям, не трогает ручные решения и отменяется одним действием. Для каждого контрагента можно открыть список его операций и поменять назначение отдельной операции.
- **Повторный импорт без двойного учёта.** Выписки одного счёта с пересекающимися периодами не дублируют операции; законные одинаковые операции в один день сохраняются. После загрузки показывается отчёт: сколько операций добавлено, сколько пропущено как уже загруженные и сколько операций прежних выписок отсутствуют в новой (они не удаляются, а требуют проверки).
- **Удаление выписки** вместе с операциями. Если позже загружены выписки той же карты за пересекающийся период, они удаляются вместе с ней: общие операции хранятся только в ранней выписке. Перед удалением показывается, что именно будет удалено.
- **База знаний продавцов.** Нормализация названий, алиасы и категории только для организаций. Имена частных лиц в общую базу не попадают.
- **Web-интерфейс** на Thymeleaf и **REST API** с OpenAPI (`/swagger-ui.html`).

## Архитектура

Монолит на Spring Boot, организованный по функциональным областям:

```text
com.esep
├── statementimport     импорт выписок: PDF → разбор → сверка → сохранение
│   └── kaspi           формат Kaspi Gold и его правила движения денег
├── moneyflow           типы движения, назначения, личные правила, отчёт
├── merchantrecognition нормализация и распознавание продавцов
├── merchantresolver    поиск по каталогу и алиасам
├── merchantmanagement  база знаний продавцов и подтверждение неизвестных описаний
├── analytics           агрегаты и dashboard
├── persistence         JPA-адаптеры портов и read-запросы
└── security            защита локального режима
```

Поток импорта:

```text
PDF ─► PdfBoxTextExtractor ─► KaspiStatementParser (строки, шапка, сверка итогов)
    ─► OverlappingOperationFilter (операции, уже сохранённые из выписок того же счёта)
    ─► распознавание продавца (только для покупок)
    ─► MoneyFlowClassifier банка ─► назначение по личным правилам
    ─► PostgreSQL
```

Новый банк добавляется реализацией `StatementParser` и, при необходимости, `MoneyFlowClassifier`; остальная система от формата банка не зависит.

## Безопасность и данные

- Ошибки, ответы API и логи не содержат описаний, сумм и контрагентов операций.
- Исходный PDF не сохраняется; из шапки читаются только период, итоги и последние 4 цифры маски карты.
- Локальный режим: Spring Security без входа, CSRF-токен для форм, проверка `Origin` для изменяющих запросов к API, проверка заголовка `Host` против DNS rebinding, лимиты 5 МБ на файл и 200 страниц PDF.
- Импорт PDF: проверка сигнатуры и структуры до разбора, отказ для PDF под паролем, постраничный разбор с ограничением времени и объёма текста, лимит памяти PDFBox; ответы 400/413/422 без содержимого файла.
- Профиль `prod` намеренно не запускается, пока не реализованы аутентификация и изоляция пользователей.
- Тестовые данные синтетические; реальные выписки в репозиторий не добавляются.

## Запуск

Требования: JDK 21, Maven 3.9+, Docker.

```bash
docker compose up -d
```

```bash
mvn spring-boot:run
```

Приложение откроется на `http://127.0.0.1:8080`, при старте Flyway применит миграции.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `DB_URL`, `DB_USERNAME`, `DB_PASSWORD` | `jdbc:postgresql://localhost:15432/esep`, `esep`, `esep` | подключение к PostgreSQL |
| `SERVER_ADDRESS`, `SERVER_PORT` | `127.0.0.1`, `8080` | адрес и порт |
| `ESEP_ALLOWED_HOSTS` | `localhost,127.0.0.1` | разрешённые значения заголовка `Host` |
| `ESEP_MAX_UPLOAD_FILE_SIZE` | `5MB` | максимальный размер выписки |
| `ESEP_MAX_PDF_PAGES` | `200` | максимальное число страниц PDF |
| `ESEP_MAX_PDF_PARSE_DURATION` | `20s` | максимальное время разбора PDF |
| `ESEP_MAX_PDF_TEXT_CHARACTERS` | `2000000` | максимальный объём извлечённого текста |
| `ESEP_MAX_PDF_MEMORY` | `64MB` | лимит памяти буферов PDFBox |

## Тесты

```bash
mvn test
```

- Unit-тесты разбора, правил движения денег, отчёта и дедупликации.
- `@DataJpaTest` на H2 для запросов и адаптеров.
- Testcontainers: все миграции Flyway и запросы разметки проверяются на одноразовой PostgreSQL 16; без Docker эти тесты пропускаются.
- Тесты на реальной выписке включаются только явно и читают файл вне репозитория:

```bash
mvn test -Dkaspi.pdf.path=/path/outside/repository/statement.pdf
```

CI: GitHub Actions (тесты), CodeQL и Dependabot.

## Ограничения

- Поддерживается только Kaspi Gold на русском языке; казахский и английский варианты выписки и другие банки не проверены.
- Назначение задаётся для контрагента целиком; экрана для решения по отдельной операции пока нет.
- Нет пользователей, входа и удаления аккаунта (удаление отдельной выписки есть) — это обязательные условия публичной версии (ADR-0005).
- Продуктовая гипотеза о целевой аудитории проверяется экспериментами E1–E3 ([материалы](docs/research/experiments/)).
