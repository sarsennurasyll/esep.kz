# ADR-0006: Удаление выписки

- Статус: принято 2026-10-29; реализовано
- Дата: 2026-10-29
- Связано: [ADR-0004](0004-overlapping-statement-deduplication.md), раздел «Хранение и удаление» в [ADR-0005](0005-path-to-production.md), M8 в [DEVELOPMENT_ROADMAP.md](../research/DEVELOPMENT_ROADMAP.md)

## Контекст

Пользователь должен иметь возможность удалить загруженную выписку: загружен не тот файл, нужно начать заново, данные больше не нужны. ADR-0005 требует, чтобы удаление выписки удаляло операции и решения по ним.

Сложность — дедупликация из ADR-0004. Если выписка B того же счёта загружена после выписки A и их периоды пересекаются, операции общего периода сохранены только в A, а из B пропущены. Удаление одной A оставит в периоде B пропуск. Его не видно ни в отчёте, ни в отметке полноты месяца, потому что период B по-прежнему покрывает эти даты.

## Варианты

### A. Удалять выписку отдельно
Просто, но тихо искажает отчёт в описанном выше случае.

### B. Запрещать удаление, пока есть зависящие выписки
Корректно, но заставляет пользователя самому искать и удалять выписки в правильном порядке.

### C. Удалять выписку вместе с зависящими от неё (выбрано)
Зависящие выписки — выписки того же банка и той же маски карты, импортированные позже и пересекающиеся по периоду; связь транзитивна. Пользователь видит план (какие выписки и сколько операций) и подтверждает его целиком.

### D. Переносить общие операции в более позднюю выписку
Сохраняет больше данных, но требует сопоставления по тому же неточному ключу, что и при импорте; ошибка переноса незаметна. Отложено до появления реальной потребности.

## Решение

Вариант C:

1. План удаления: выбранная выписка и все выписки, импортированные после неё (больший `id`) с тем же банком и маской карты и пересекающимся периодом, по цепочке. Выписки без определённой карты не сравнивались при импорте и удаляются по одной.
2. Клиент передаёт весь набор выписок из плана. Если набор на сервере уже другой (например, между показом и подтверждением загрузили ещё одну выписку), ничего не удаляется: API отвечает 409 с кодом `STATEMENT_DELETION_MISMATCH`, страница показывает новый план.
3. Удаляются операции и выписки — физически, без «мягкого» удаления: данные финансовые и персональные. После удаления тот же файл можно загрузить снова.
4. Личные правила контрагентов и база продавцов не удаляются: они не принадлежат одной выписке. Правила удаляются на странице назначений.

## Последствия

- Удаление ранней выписки может удалить и более поздние; это явно показано до подтверждения.
- Удаление аккаунта и всех данных пользователя появится вместе с пользователями (ADR-0005).
- Если пользователю понадобится сохранять поздние выписки при удалении ранней, вернуться к варианту D.
