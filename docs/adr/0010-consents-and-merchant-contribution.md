# ADR-0010: Согласия с версиями и пополнение базы магазинов

- Статус: принято 2026-10-31; реализовано; тексты документов — черновики до проверки юристом
- Дата: 2026-10-31
- Связано: [ADR-0007](0007-one-time-check-and-accounts.md), [ADR-0008](0008-accounts-and-login.md), [ADR-0009](0009-data-isolation.md)

## Контекст

ADR-0007 требует всех согласий на сайте, записи о принятой версии документа и отдельного необязательного согласия на пополнение базы магазинов: только названия, без сумм, дат и связи с человеком.

## Решение

1. **Документы.** `/privacy` и новое `/terms` открыты без входа и показывают версию. Версии заданы в `LegalDocument`: изменённый текст обязательного документа требует новой версии.
2. **Журнал.** `user_consents` (миграция `V17`): учётная запись, документ, версия, дано или отозвано, время. Строки только добавляются; текущее состояние — последняя строка. IP и браузер не хранятся: это лишние персональные данные.
3. **Регистрация.** Аккаунт и записи о согласиях создаются одной транзакцией.
4. **Новая версия.** Пока текущие версии обязательных документов не приняты, страницы полного анализа ведут на `/consent`, а API отвечает 403 `CONSENT_REQUIRED`. Открыты документы, разовая проверка и страница аккаунта: несогласный должен иметь возможность удалить данные. Аккаунты, созданные до этого эпика, тоже увидят запрос: версия их согласия не записана.
5. **Разовая проверка.** Согласие проверяется в запросе и никуда не записывается: посетитель анонимен, а хранить ничего не обещано.
6. **Пополнение базы.** Необязательно, по умолчанию выключено, включается при регистрации или на странице аккаунта. Согласие действует только на текущую версию текста.
7. **Что передаётся.** В `merchant_suggestions` — только нормализованное название и статус. Нет ни владельца, ни суммы, ни даты: связь с человеком отсутствует в самой схеме.
8. **Откуда берутся названия.** Только нераспознанные операции типа «покупка»: переводы могут содержать имена людей. Названия, похожие на имя, отсекает `PersonalNameDetector`. Сбор идёт при включении согласия и после каждого импорта.
9. **Проверка человеком.** Названия не попадают в общую базу сами. Администратор видит список на `/knowledge-base/suggestions`, добавляет через базу знаний или отклоняет; отклонённое не возвращается.

## Последствия

- Уже переданное название нельзя отозвать: оно ни с кем не связано. Политика говорит об этом прямо; отзыв прекращает новую передачу.
- При удалении аккаунта журнал согласий удаляется вместе с ним. Нужно ли хранить доказательство согласия после удаления — вопрос юристу.
- Детектор имён эвристический: редкое имя без инициалов может попасть в список предложений. В общую базу оно не пройдёт без решения администратора, но хранится в списке, пока его не отклонят. Отклонённое название тоже остаётся в таблице, чтобы не возвращаться.
- Смена версии документа требует правки кода; тексты живут в шаблонах, прошлые версии — в истории Git.
- Тексты не проверены юристом, реквизитов оператора нет. Это условие публикации.
